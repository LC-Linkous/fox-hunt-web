Tuning Debugging

The firmware installer is below, and the pins page shows where the two optional wires go.

1Connect a fox, then Start receiver on the fox's channel — or Seek to find it.
  1. Get on the channel. Start receiver listens where the fox is tuned (Receiver presets, or the event channels under Setup). Seek steps through the channels and stops where something is on.
  2. Read the big number. RSSI is the module's 0–255 strength byte: warmer / colder, not metres. It climbs as you walk toward the fox and as the antenna points at it. Max remembers the best you have seen.
  3. Wait for the fox to key. Foxes transmit in bursts. After two bursts the countdown says when the next one comes: move during the gap, measure during the burst.
  4. Take a bearing during a burst. With a directional antenna: hold Capture, turn a full circle, release. The lobe's centre is the direction. Two bearings from two places give a fix.
  5. Too strong? When RSSI pins at the top, add attenuation (the dropdown is bookkeeping; the attenuator is in the coax) or swap to a worse antenna, and keep walking.
  6. Pin what you find. The hunt board keeps each fox's channel, ID, last-heard time and cycle. Audio from a sound card decodes the fox's Morse ID into the board.

Fox console

Firmware for the fox

The fox needs this page's code.py on it once. The XIAO ESP32-C3 has no USB drive, so the page writes the file through CircuitPython's REPL over the same USB serial connection — the same thing Thonny does — and reboots into it. Every fox is assumed to be running CircuitPython already (the stock DC34 fox is).

A setting the firmware keeps on the board, applied right after the install; one code.py serves every fox.

Stored on the board too. Needed before the transmitter can ever be armed.

firmware —

What "Install" does, and doing it by hand
  1. Opens the fox's serial port (Chrome or Edge; the chooser lists USB devices). If the fox is already connected to this page, that connection is used.
  2. Interrupts whatever code.py is running (Ctrl+C), enters CircuitPython's raw REPL, writes the new file as code.py.new, then renames it over code.py — so a failed transfer leaves the old firmware in place.
  3. Soft-reboots the board and waits for the new firmware's ch> prompt, then applies the band and callsign above.

By hand instead: download code.py, open it in Thonny with the interpreter set to CircuitPython (generic) on the fox's port, File → Save As → CircuitPython device as exactly code.py, Ctrl+D. Then disconnect Thonny — it holds the port — and connect here. A board that has never had CircuitPython flashed needs that first: dc34fox, step 1.

Going back to the stock beacon: install dc34fox's code.py the same way (Thonny), or any code.py through this page's console is out of scope — this installer only writes this project's firmware.
